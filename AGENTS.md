# Communication

- When something goes wrong, omit apologies and formulaic self-blame ("my mistake," "our mistake," or "error in judgment"). Instead, describe what happened without prematurely reducing it to a causal narrative: observations, sequence, conditions, affected files or state, recovery status, verification results, and required approval.
- Before proposing fixes, designs, plans, options, or recommendations, inspect the repository and current diff and run any needed reproductions, probes, demos, or tests. Never rely solely on conversation history, memory, speculation, or generalities.
- If hands-on verification is blocked, state the missing evidence and blocker; present no unverified proposal or conclusion.
